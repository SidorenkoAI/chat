# Урок 5. JSON-протокол и имена пользователей — теория и разбор кода

Сегодня у каждого участника чата появляется **ник**, сообщения подписываются именем, при входе и выходе все видят уведомление, а команда `/who` показывает, кто сейчас в сети. Чтобы всё это стало возможным, мы меняем **формат сообщений**: вместо простых строк — JSON-объекты.

Структура проекта — та же, что на уроке 4. Меняются три файла: `common/protocol.py`, `server/core.py`, `client/__main__.py`.

## Зачем менять протокол

Раньше сообщение было просто строкой текста. Но чату теперь нужно передавать **разные виды** информации:
- обычное сообщение от человека;
- «Аня вошла в чат» (системное уведомление);
- список пользователей онлайн;
- ошибку («имя занято»).

Если всё это — просто строки, получатель не может отличить одно от другого. Можно было бы придумать правило «системные начинаются со звёздочки», но что если человек сам напишет сообщение со звёздочки? Такие самодельные правила легко ломаются.

Решение — передавать **структурированные** сообщения, у которых есть поле `type` («что это за сообщение») и другие поля по необходимости.

## Подробный разбор: что такое JSON

**JSON** — текстовый формат записи данных, очень похожий на словари и списки Python:

```json
{"type": "message", "from": "Аня", "text": "привет"}
{"type": "who_reply", "users": ["Аня", "Боря"]}
```

Модуль `json` из стандартной библиотеки переводит данные туда и обратно:
- `json.dumps(obj)` — Python-объект (словарь, список…) → строка JSON (**dump s**tring — «выгрузить в строку»);
- `json.loads(text)` — строка JSON → Python-объект (**load s**tring — «загрузить из строки»).

Важная для нас деталь: `json.dumps` по умолчанию записывает объект **в одну строку**, без переводов строки внутри. Значит, наш старый протокол «одно сообщение = одна строка с `\n` в конце» продолжает работать без изменений. Меняется только **содержимое** строки: теперь это JSON.

## Шаг 1. `common/protocol.py`

```python
import json
import socket
from collections.abc import Iterator


def send_json(sock: socket.socket, obj: dict) -> None:
    line = json.dumps(obj, ensure_ascii=False)
    sock.sendall((line + "\n").encode("utf-8"))


def iter_json(sock: socket.socket) -> Iterator[dict]:
    reader = sock.makefile("r", encoding="utf-8", newline="\n")
    for line in reader:
        line = line.rstrip("\n")
        if line:
            yield json.loads(line)
```

Функции `send_line`/`iter_lines` из урока 4 заменены на `send_json`/`iter_json`.

**`send_json(sock, obj)`** — отправить один объект:
- `json.dumps(obj, ensure_ascii=False)` — превращаем словарь в строку JSON. Параметр `ensure_ascii=False` нужен ради кириллицы: без него `"привет"` превратилось бы в нечитаемое `"пр..."`. Работать работало бы, но читать логи и отлаживать неудобно.
- дальше — привычное: `\n` в конце, перевод в байты, `sendall`.

**`iter_json(sock)`** — генератор, выдающий полученные объекты по одному:
- `reader = sock.makefile(...)` — читаем сокет построчно, как раньше;
- `line = line.rstrip("\n")` — отрезаем разделитель;
- `if line:` — пропускаем пустые строки: `json.loads("")` выбросил бы ошибку;
- `yield json.loads(line)` — превращаем строку обратно в словарь и отдаём.

Благодаря уроку 4 протокол живёт в одном файле, и замена формата свелась к правке этого файла плюс мест, где его используют.

## Шаг 2. Типы сообщений нашего протокола

| Кто отправляет | `type` | Остальные поля | Смысл |
|---|---|---|---|
| клиент | `join` | `username` | «хочу войти под этим ником» (первое сообщение) |
| клиент | `message` | `text` | обычное сообщение в чат |
| клиент | `who` | — | «кто сейчас в сети?» |
| сервер | `message` | `from`, `text` | сообщение от участника |
| сервер | `system` | `text` | уведомление (вход/выход) |
| сервер | `who_reply` | `users` | список ников онлайн |
| сервер | `error` | `text` | ошибка |

Обрати внимание: поле `from` в сообщении ставит **сервер**, а не клиент. Иначе любой клиент мог бы прислать `{"from": "Учитель", ...}` и выдать себя за другого.

## Шаг 3. `server/core.py`

### 3.1. Импорты и конструктор

```python
from common.protocol import iter_json, send_json
...
class ChatServer:
    def __init__(self, host: str, port: int):
        self.host = host
        self.port = port
        self.clients: dict[str, socket.socket] = {}
        self.lock = threading.Lock()
```

Главное изменение: `self.clients` теперь **словарь** `{ник: сокет}`, а не список сокетов. Зачем:
- по нику можно мгновенно найти сокет человека (пригодится на уроке 8 для личных сообщений);
- легко проверить, не занят ли ник: `username in self.clients`;
- список ников для `/who` — это просто ключи словаря.

### 3.2. Рассылка

```python
    def broadcast(self, obj: dict) -> None:
        with self.lock:
            for conn in self.clients.values():
                send_json(conn, obj)
```

- теперь рассылаем не строку, а словарь (`obj`);
- `self.clients.values()` — перебираем **значения** словаря, то есть сокеты (ключи — ники — здесь не нужны).

### 3.3. Приём первого сообщения — `join`

```python
    def handle_client(self, conn: socket.socket, addr) -> None:
        messages = iter_json(conn)

        try:
            join = next(messages)
        except StopIteration:
            conn.close()
            return
```

- `messages = iter_json(conn)` — создаём генератор **один раз** и дальше пользуемся только им.
- `next(messages)` — вручную взять **одно** следующее значение из генератора, то есть первое сообщение клиента. По протоколу это должен быть `join`.
- `StopIteration` — это исключение `next` выбрасывает, если значений больше нет: клиент подключился и сразу отключился, ничего не прислав. Тогда просто закрываем соединение и выходим.

### 3.4. Проверка и регистрация ника

```python
        username = join.get("username", "").strip()
        with self.lock:
            if not username or username in self.clients:
                send_json(conn, {"type": "error", "text": "Имя занято или пустое"})
                conn.close()
                return
            self.clients[username] = conn
```

- `join.get("username", "")` — взять поле `username`, а если его нет — пустую строку. В отличие от `join["username"]`, метод `get` не падает с ошибкой `KeyError` при отсутствии ключа.
- `.strip()` — убрать пробелы по краям: ник `"  Аня "` превратится в `"Аня"`.
- Проверку «ник не пустой и не занят» и добавление в словарь делаем под **одной** блокировкой. Если бы проверка и добавление были под разными `with self.lock:`, два клиента с одинаковым ником могли бы одновременно пройти проверку и оба добавиться.
- `self.clients[username] = conn` — запоминаем: у этого ника вот такой сокет.

### 3.5. Уведомление о входе

```python
        logger.info("%s подключился (%s)", username, addr)
        self.broadcast({"type": "system", "text": f"{username} присоединился к чату"})
```

Рассылаем всем (включая самого вошедшего) системное сообщение.

### 3.6. Основной цикл

```python
        try:
            for msg in messages:
                if msg["type"] == "message":
                    self.broadcast({"type": "message", "from": username, "text": msg["text"]})
                elif msg["type"] == "who":
                    with self.lock:
                        online = list(self.clients.keys())
                    send_json(conn, {"type": "who_reply", "users": online})
```

- `for msg in messages:` — **тот же** генератор, из которого мы уже взяли `join`. Цикл продолжит с **второго** сообщения — ничего не потеряется и не повторится.
- `msg["type"]` — смотрим, что за сообщение пришло, и выбираем действие (`if`/`elif`).
- Для `message` сервер собирает **новый** словарь: добавляет `from` (ник, который сервер знает сам) и берёт из присланного только `text`.
- Для `who`:
  - `list(self.clients.keys())` — список ников. Делаем копию под блокировкой, чтобы словарь не поменялся, пока мы его читаем;
  - ответ отправляем **только** спросившему (`send_json(conn, ...)`), а не всем.

### 3.7. Выход клиента

```python
        finally:
            with self.lock:
                self.clients.pop(username, None)
            conn.close()
            logger.info("%s отключился", username)
            self.broadcast({"type": "system", "text": f"{username} вышел из чата"})
```

- `self.clients.pop(username, None)` — удалить ник из словаря. Второй аргумент `None` значит «если такого ключа уже нет — не падать».
- Уведомление о выходе рассылаем **после** удаления — ушедшему оно уже не отправляется.

Метод `run()` и файл `server/__main__.py` не изменились.

## Шаг 4. `client/__main__.py`

### 4.1. Разбор входящих сообщений

```python
def receive_loop(messages) -> None:
    for msg in messages:
        if msg["type"] == "message":
            print(f"\n{msg['from']}: {msg['text']}\n> ", end="")
        elif msg["type"] == "system":
            print(f"\n* {msg['text']}\n> ", end="")
        elif msg["type"] == "who_reply":
            print(f"\nОнлайн: {', '.join(msg['users'])}\n> ", end="")
        elif msg["type"] == "error":
            print(f"\nОшибка: {msg['text']}\n> ", end="")
```

- Функция теперь получает не сокет, а готовый генератор `messages`.
- Для каждого `type` — своё оформление. Внутри f-строки в двойных кавычках ключи пишем в **одинарных**: `msg['from']`.
- `', '.join(msg['users'])` — склеить список ников в одну строку через запятую: `["Аня", "Боря"]` → `"Аня, Боря"`.

### 4.2. Вход в чат

```python
    sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    sock.connect((args.host, args.port))

    username = input("Ваш ник: ").strip()
    send_json(sock, {"type": "join", "username": username})

    messages = iter_json(sock)
    threading.Thread(target=receive_loop, args=(messages,), daemon=True).start()
```

- После подключения спрашиваем ник и первым сообщением отправляем `join` — как требует протокол.
- Создаём генератор `messages` и передаём его в поток приёма.

### 4.3. Команды пользователя

```python
    print("Соединение установлено. Команда /who — список пользователей онлайн.")
    while True:
        text = input("> ")
        if text == "/who":
            send_json(sock, {"type": "who"})
        else:
            send_json(sock, {"type": "message", "text": text})
```

Всё, что начинается с `/`, — команды для программы, остальное — сообщения в чат. Пока команда одна: `/who`.

## Подробный разбор: `next()` и общий генератор

Генератор помнит, где остановился. Поэтому на сервере работает такой приём:

```python
messages = iter_json(conn)
join = next(messages)      # взяли первое сообщение
for msg in messages:        # продолжаем со второго
    ...
```

А вот так делать **нельзя**:

```python
join = next(iter_json(conn))   # создали генератор №1
for msg in iter_json(conn):     # создали генератор №2 — у него свой makefile и свой буфер
```

Каждый вызов `iter_json` создаёт новый объект `makefile` со своим буфером. Первый мог уже «заглотить» из сокета больше одной строки — и эти строки пропадут. Правило: **один сокет — один генератор**.

## Подробный разбор: `dict.get` против `dict[...]`

```python
msg["type"]            # если ключа нет — KeyError, поток клиента упадёт
msg.get("type")        # если ключа нет — None
msg.get("type", "")    # если ключа нет — пустая строка
```

Данные, пришедшие по сети, — **чужие**: мы не контролируем, что пришлёт клиент. Где отсутствие поля — нормальная ситуация, удобнее `get`. В нашем коде `msg["type"]` без проверки — осознанное упрощение (одно из заданий — сделать надёжнее).

Из папки урока, в разных вкладках терминала:


Войди под разными никами. Сообщения подписаны, вход/выход видят все, `/who` показывает список.

## Частые ошибки и ограничения

- **Два клиента с одинаковым ником** — сервер отклонит второго, но клиент этого не ждёт: он уже пишет в закрытое соединение и получит ошибку. Нормальный обмен «запрос — ответ» при входе сделаем на уроке 7 (или в задании этого урока).
- **`JSONDecodeError`** — пришло что-то, что не является JSON. Например, к серверу урока 5 подключился клиент урока 4. Разные версии протокола несовместимы — это нормально.
- **Кириллица превратилась в `а...`** — забыли `ensure_ascii=False`. На работу не влияет, но читать неудобно.
