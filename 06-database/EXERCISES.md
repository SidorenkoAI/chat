# Урок 6. Задания на доработку кода

Два правила на весь урок:
1. Любые данные от пользователя попадают в SQL **только через `?`**.
2. Любое обращение к базе на сервере — **под `self.lock`**.

Если меняешь структуру таблиц, удали старый `chat.db`: `CREATE TABLE IF NOT EXISTS` не добавляет новые столбцы в уже существующую таблицу.

---

## Лёгкие

### 1. Время в истории

Сообщения истории показываются со временем: `[история 14:05] Аня: привет`, причём время — **местное**, а не UTC.

- SQLite умеет переводить время: `datetime(created_at, 'localtime')`. Куда это вставить — в запрос `SELECT` или в `CREATE TABLE`? Чем отличаются варианты для уже сохранённых сообщений?
- Время приходит строкой `"2026-09-27 14:05:31"`. Как срезом строки взять только `14:05`?

### 2. «Конец истории»

После сообщений истории новый участник видит строку `— конец истории —`. Если история пустая — строки нет.

- Какой уже существующий тип сообщения подойдёт, чтобы не менять клиент?
- Пустой список в `if` считается ложью — как этим воспользоваться?

### 3. Счётчик сообщений при старте

При запуске сервер пишет в лог: «В базе сообщений: 42».

- Новая функция в `db/storage.py`, например `count_messages(conn)`. SQL: `SELECT COUNT(*) FROM messages`.
- `fetchone()` вернёт кортеж из одного элемента — как достать само число?
- Где удобно вызвать: в конструкторе сервера сразу после открытия базы.

## Средние

### 4. Команда `/history N`

`/history 50` — показать последние 50 сообщений (не больше 100).

- Придумай сообщение протокола: например, `{"type": "history_request", "limit": 50}`. Ответ сервера — те же сообщения `history`.
- На клиенте: `int(...)` от неверного текста выбросит `ValueError` — поймай и выведи подсказку, ничего не отправляя.
- На сервере: данные от клиента — чужие. Проверь, что `limit` — действительно число (`isinstance`), и ограничь его сверху.

### 5. Поиск: `/search слово`

Показать до 20 последних сообщений, в тексте которых встречается слово.

- SQL: `WHERE text LIKE ?`. Знак `%` в шаблоне значит «любые символы», поэтому параметр — `f"%{слово}%"`. Сам `%` пишем в **параметре**, а не в тексте запроса.
- Новый тип ответа, например `search_reply` со списком найденного. Как клиенту показать «ничего не найдено»?
- Для кириллицы `LIKE` в SQLite различает большие и маленькие буквы — проверь и объясни, что видишь.

### 6. Статистика: `/stats`

Топ-3 самых активных участников: «Аня — 15 сообщений, Боря — 9…».

- SQL: `GROUP BY from_user` — сгруппировать строки по автору; `COUNT(*)` — посчитать в каждой группе; `ORDER BY ... DESC LIMIT 3`.
- Ответ сервера — новый тип со списком пар «ник — количество».

## Посложнее

### 7. «Был в сети»: `/lastseen ник`

Ответ: «Аня сейчас в чате», «Аня была в чате 27.09 в 14:05» или «Аня ещё не заходила».

- Нужна новая таблица, например `last_seen (username TEXT PRIMARY KEY, seen_at TEXT)`.
- Когда записывать время? В `finally`, когда человек выходит.
- Запись «добавить, а если уже есть — обновить» в SQLite делается одним запросом: `INSERT ... ON CONFLICT(username) DO UPDATE SET seen_at = excluded.seen_at`.
- Порядок проверок: сначала «онлайн ли сейчас» (словарь клиентов), потом база.

### 8. Экспорт истории в CSV

Отдельный скрипт `export_history.py` выгружает все сообщения в файл, который открывается в Excel: `python export_history.py history.csv`.

- Модуль `csv`, `csv.writer(файл, delimiter=";")` — русский Excel ждёт разделитель `;`.
- Файл открывай с `newline=""` (так требует модуль `csv`) и `encoding="utf-8-sig"` — иначе Excel покажет кириллицу «кракозябрами».
- Запрос к базе лучше оформить функцией в `db/storage.py`, а не писать SQL в скрипте.
- Скрипт запускается как обычный файл из папки урока — почему у него сработает `from db.storage import ...`?
