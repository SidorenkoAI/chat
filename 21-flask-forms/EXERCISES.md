## Лёгкие

### 1. Длина сообщения — на сервере

Сейчас длину текста проверяет только браузер (`maxlength="500"`). Удалите атрибут в F12 → Elements и отправьте длинный текст: сервер его примет. Сделайте так, чтобы сервер отвечал ошибкой «Сообщение длиннее 500 символов» с кодом 400.

- Константа `MAX_TEXT` уже есть, но нигде не используется.
- Посмотрите, как сделана проверка длины имени.
- Проверьте и из Python, без браузера:
  ```python
  import urllib.request, urllib.parse
  data = urllib.parse.urlencode({"name": "Хакер", "text": "x" * 1000}).encode()
  urllib.request.urlopen("http://127.0.0.1:5000/send", data)  # должна быть ошибка 400
  ```

### 2. Автообновление

Страница сама обновляется каждые 10 секунд, и новые сообщения появляются без нажатия «обновить».

- В HTML есть специальный тег для этого: `<meta http-equiv="refresh" content="10">`. Он ставится в `<head>`. В каком шаблоне `<head>`? Нужно ли автообновление на странице «О чате»? Подумайте, как добавить тег только на страницу чата.
- После ошибки в форме адрес страницы — `/send`. Что сделает браузер, если просто «обновит» её? Подсказка: у тега есть вариант с адресом, `content="10; url=..."`.
- Начните набирать длинное сообщение и подождите 10 секунд. Что случилось с текстом? Это главный минус способа. На уроке 22 сделаем по-настоящему.

### 3. Сообщения со смайликами

При отправке `:)` заменяется на 🙂, `:(` — на 🙁, `<3` — на ❤️.

- Где делать замену: в шаблоне при показе (как в задании 8 урока 20) или на сервере при сохранении? Сделайте на сервере, в `send()`.
- Чем отличаются эти варианты? Подумайте, что увидит человек, который потом прочитает сообщения из файла или базы.

## Средние

### 4. Имя в cookie

Имя не передаётся в адресе. Сайт запоминает его в **cookie**: открыл чат завтра — поле «Имя» уже заполнено.

- **Cookie** — маленькая заметка, которую сайт просит браузер хранить и присылать обратно с каждым запросом к этому сайту.
- Записать: у ответа есть метод `set_cookie(имя, значение, max_age=секунды)`. Ответ — то, что вернул `redirect(...)`: сохраните его в переменную, вызовите `set_cookie` и верните.
- Прочитать: `request.cookies.get("name", "")`.
- Посмотрите cookie в F12 → Application → Cookies. Поменяйте значение прямо там и обновите страницу. Что это говорит о безопасности? Можно ли по cookie понять, кто пишет на самом деле?

### 5. Сохранение в файл

Сообщения не пропадают после перезапуска сайта: они хранятся в файле `messages.json`.

- При запуске программы: если файл есть — прочитать список из него (`json.load`), если нет — пустой список.
- После каждого нового сообщения — записать весь список в файл (`json.dump`, `ensure_ascii=False`, чтобы кириллица читалась). Делать это нужно под тем же замком. Почему?
- Откройте `messages.json` в редакторе и посмотрите, что там.
- В уроке 23 вместо файла будет настоящая база данных SQLite из урока 6.

### 6. Поиск по чату

Страница `/search?q=привет` показывает только сообщения, в которых есть слово «привет» (без учёта регистра), и пишет, сколько найдено. В шапке — маленькая форма поиска.

- Поиск ничего не меняет на сервере. Какой метод выбрать для формы поиска: GET или POST? Как после отправки будет выглядеть адрес? Можно ли такой ссылкой поделиться?
- Поле формы поиска называется `q`, на сервере это `request.args.get("q", "")`.
- Без учёта регистра: сравнивайте `.lower()` обеих строк.
- Шаблон результатов можно сделать на основе `index.html` или отдельный.

## Посложнее

### 7. Антиспам

Один человек (одно имя) может отправлять не больше одного сообщения в 3 секунды. Слишком частое — ошибка «Не так быстро!» с кодом **429** (Too Many Requests).

- Нужен словарь «имя → время последнего сообщения».
- Время — `time.monotonic()`: оно не скачет, если на компьютере переведут часы.
- Словарь читают и меняют разные потоки. Что нужно?
- Подумайте: спамер может каждый раз писать под новым именем. Что с этим делать? Пока — ничего. Это ещё одна причина сделать вход по паролю (урок 23).

### 8. Личные сообщения — и почему без пароля они не личные

В форме есть необязательное поле «Кому». Если оно заполнено, сообщение личное: его видят только автор и получатель, с пометкой «Лично для …» / «Лично от …» и пунктирной рамкой (класс `private` уже есть в CSS).

- В словарь сообщения добавьте ключ `to` (для общих сообщений `None`).
- Отбирать, кому что показывать, лучше в Python (в `render_chat`), а не в шаблоне. Почему? Подумайте, что увидит человек, который откроет «Просмотр кода страницы».
- А теперь — главное. Боря пишет Ане лично. Может ли Вова прочитать это сообщение, ничего не взламывая? Подсказка: посмотрите на адрес страницы. Напишите ответ комментарием в коде. Это ровно та проблема, которую решает урок 23.
