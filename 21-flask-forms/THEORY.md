# Урок 21. Формы: чат без JavaScript — теория и разбор кода

До сих пор браузер только **получал** страницы. Сегодня он начинает **отправлять** данные на сервер, а сервер — их запоминать. Получается настоящий чат, хоть и простой.

## Как форма отправляет данные

```html
<form id="send-form" method="post" action="/send">
  <input name="name" value="Аня">
  <input name="text" value="Привет!">
  <button type="submit">Отправить</button>
</form>
```

Когда нажимают «Отправить» (или Enter в поле), браузер:
1. собирает все поля формы, **у которых есть атрибут `name`**;
2. превращает их в строку `name=Аня&text=Привет!` (кириллица и пробелы при этом кодируются, как в адресах);
3. отправляет запрос на адрес из `action` способом из `method`;
4. показывает то, что ответил сервер, как новую страницу.

В уроке 13 мы останавливали это поведение (`event.preventDefault()`), потому что сервера не было. Сегодня форма делает то, для чего создана.

### GET и POST

| | GET | POST |
|---|---|---|
| Для чего | **получить** страницу | **отправить** данные, которые что-то меняют |
| Где данные | в адресе: `/hello?name=Аня` | в теле запроса, в адресе их не видно |
| Когда | ссылки, адресная строка, поиск | регистрация, вход, новое сообщение, заказ |
| Можно повторить | да, ничего не изменится | повтор = ещё одно сообщение, ещё один заказ |
| В `<form>` | `method="get"` (по умолчанию) | `method="post"` |

Правило простое: если запрос **меняет** что-то на сервере, это POST. Поисковики ходят по ссылкам (GET) и не должны случайно «нажать» на добавление сообщения.

## Разбор `app.py`

```python
import threading
from datetime import datetime

from flask import Flask, redirect, render_template, request, url_for
```

Новое из Flask:
- `request` — текущий запрос: адрес, данные формы, параметры;
- `redirect` — ответ «иди на другой адрес»;
- `url_for` уже знаком по шаблонам (урок 20), в Python он работает так же.

```python
MAX_NAME = 30
MAX_TEXT = 500
MAX_MESSAGES = 50

messages = []
lock = threading.Lock()
```

- Все сообщения — в обычном списке. Он живёт в памяти программы, поэтому после перезапуска сайта чат пуст. Сохранять в файл можно в задании 5, в базу данных — в уроке 23.
- **Замок.** Flask обслуживает каждый запрос в отдельном потоке, как наш сервер в уроке 3 обслуживал каждого клиента. Если Аня и Боря нажмут «Отправить» одновременно, два потока одновременно полезут в `messages`. Замок пускает их по одному.

### Функция-помощник

```python
def render_chat(name="", text="", error=None, status=200):
    with lock:
        shown = list(messages)
    return render_template("index.html", messages=shown, name=name, text=text, error=error), status
```

Страницу чата нужно показывать в двух местах: на главной и при ошибке в форме. Чтобы не повторять код, он вынесен в функцию.

- `list(messages)` — **копия** списка. Пока шаблон её читает, другой поток может добавить сообщение в настоящий список. Копию никто не тронет, поэтому замок нужен только на миг копирования.
- `name` и `text` — что подставить в поля формы: после ошибки ученик не должен набирать сообщение заново.
- Функция возвращает пару «HTML, код ответа» (урок 19).

### Главная страница

```python
@app.route("/")
def index():
    return render_chat(name=request.args.get("name", ""))
```

Имя берётся из адреса: `/?name=Аня`. Его туда подставит перенаправление после отправки (ниже). Так сайт «помнит», кто вы, от одного запроса к другому.

### Приём формы

```python
@app.route("/send", methods=["POST"])
def send():
    name = request.form.get("name", "").strip()
    text = request.form.get("text", "").strip()
```

- `methods=["POST"]` — этот адрес принимает только POST. По умолчанию маршрут принимает только GET. Если открыть `/send` в адресной строке, будет ошибка **405 Method Not Allowed**: «так сюда нельзя».
- `request.form` — данные формы, «почти словарь»: ключи — атрибуты `name` полей, значения — что в них ввели.
- `.get("name", "")` — если поля нет, то пустая строка. `request.form["name"]` в такой ситуации вызвал бы ошибку 400.
- `.strip()` убирает пробелы по краям: сообщение из одних пробелов станет пустым.

```python
    if not name or not text:
        return render_chat(name, text, error="Нужно написать имя и сообщение", status=400)
    if len(name) > MAX_NAME:
        return render_chat(name, text, error=f"Имя длиннее {MAX_NAME} символов", status=400)
```

**Проверка на сервере.** В форме уже есть `required` и `maxlength`, зачем проверять ещё раз? Эти атрибуты проверяет **браузер**, а браузер — у пользователя. Его можно обмануть: удалить атрибут в F12, отправить запрос программой на Python. Сервер должен сам проверять всё, что к нему пришло.

Код **400 Bad Request** значит «неправильный запрос». Страница при этом показывается, с ошибкой над формой.

Заметьте: длину **текста** сервер пока не проверяет, только браузер (`maxlength="500"`). Задание 1 — исправить это.

```python
    with lock:
        messages.append({"author": name, "text": text, "time": datetime.now().strftime("%H:%M")})
        del messages[:-MAX_MESSAGES]
```

- Добавляем сообщение со временем отправки.
- `del messages[:-MAX_MESSAGES]` удаляет всё, **кроме** последних 50. `messages[:-50]` — это «все, кроме последних 50» (срез с отрицательным индексом). Если сообщений меньше 50, срез пустой и ничего не удаляется. Без этого список рос бы бесконечно, а страница становилась бы всё длиннее.

```python
    return redirect(url_for("index", name=name))
```

**Перенаправление.** Вместо страницы сервер отвечает кодом **302** и заголовком `Location: /?name=Аня`. Браузер сам сразу делает GET по этому адресу. Лишние параметры `url_for` превращает в параметры адреса: `url_for("index", name="Аня")` → `/?name=%D0%90%D0%BD%D1%8F` (так кодируется кириллица).

## Подробный разбор: POST → redirect → GET

Почему бы не показать страницу чата прямо в ответ на POST?

```
Без redirect:                          С redirect:
POST /send  → страница чата            POST /send  → 302, «иди на /?name=Аня»
F5 = ещё раз POST /send                GET /?name=Аня → страница чата
   → сообщение задвоилось!             F5 = ещё раз GET /?name=Аня → просто обновилось
```

F5 повторяет **последний запрос**. Если последним был POST, браузер честно спросит «Подтвердите повторную отправку формы». Пользователь нажмёт «Да», и сообщение уйдёт второй раз. Поэтому после успешного POST всегда делают перенаправление. Этот приём так и называется: **POST/Redirect/GET**.

При ошибке (400) перенаправления нет: мы показываем форму с ошибкой и введённым текстом. Сообщение при этом не добавлено, так что повторная отправка ничего не испортит.

## Разбор `index.html`

```html
{% for m in messages|reverse %}
  <div class="message {% if m.author == name %}mine{% endif %}">
    ...
  </div>
{% else %}
  <div class="message system">Сообщений пока нет. Напишите первым!</div>
{% endfor %}
```

- `{% if m.author == name %}mine{% endif %}` — свои сообщения справа и синие. «Свои» — значит, с тем же именем, что в адресе.
- `{% else %}` у цикла — что показать, если список пуст (урок 20).
- `|reverse` — фильтр «в обратном порядке». Зачем — ниже.

### Подробный разбор: новые сообщения внизу без JavaScript

Сообщений больше, чем помещается на экране. Обычный список после загрузки страницы показывает **начало**, то есть самые старые сообщения. В уроке 13 мы прокручивали вниз из JavaScript (`messages.scrollTop = messages.scrollHeight`). Сегодня JavaScript нет.

Приём из CSS:

```css
#messages {
  display: flex;
  flex-direction: column-reverse;
}
```

`column-reverse` — колонка **снизу вверх**: первый элемент стоит внизу, второй над ним и так далее. А прокрутка такого списка начинается снизу, с первого элемента. Остаётся выдать сообщения новыми вперёд (`messages|reverse`): самое новое — первое в HTML, значит, на экране оно в самом низу, и его сразу видно.

### Форма

```html
{% if error %}
  <p class="error">{{ error }}</p>
{% endif %}

<form id="send-form" method="post" action="{{ url_for('send') }}">
  <input id="name" name="name" type="text" placeholder="Имя" value="{{ name }}" maxlength="30" required>
  <input id="text" name="text" type="text" placeholder="Сообщение…" value="{{ text }}"
         maxlength="500" autocomplete="off" required autofocus>
  <button type="submit">Отправить</button>
</form>
```

- `value="{{ name }}"` — поле сразу заполнено именем из адреса: не нужно вводить его к каждому сообщению.
- `value="{{ text }}"` — после ошибки текст сообщения не пропадает. Если `text` не передали, Jinja вставит пустоту.
- `required` — браузер не отправит форму с пустым полем; `maxlength` — не даст набрать больше символов.
- `autofocus` — после загрузки страницы курсор уже в поле сообщения: можно сразу печатать следующее.
- `autocomplete="off"` — браузер не будет подсказывать прошлые сообщения.

Почему `id` и `name` одинаковые? `id` нужен для CSS (`#name`) и для `<label for="...">`, а `name` — для отправки на сервер. Совпадать они не обязаны, но так проще.

## HTTP не помнит пользователей

Вспомним сервер из урока 5. Клиент подключился, назвал имя, и сервер помнил его, **пока соединение открыто**. У HTTP по-другому: браузер подключается, получает страницу, и на этом всё. Следующий запрос — как письмо от незнакомца.

Отсюда два следствия:
1. **Сайт не знает, кто сейчас «в сети».** Поэтому из страницы пропал список «В сети»: составить его не из чего. Вернём его в уроке 24, когда появится постоянное соединение.
2. **Имя нужно передавать с каждым запросом.** Мы кладём его в адрес (`?name=Аня`). Удобно, но кто угодно может открыть `/?name=Боря` и писать от имени Бори! Как сайту убедиться, что ты — это ты, разберём в уроке 23: вход по паролю и **сессии**.

## Безопасность

- **XSS.** Сообщения пишут люди, кто-нибудь обязательно отправит `<script>…</script>`. Шаблон экранирует каждое `{{ }}`, поэтому скрипт показывается как текст и не выполняется (подробно — в уроках 19 и 20).
- **Проверка на сервере.** Всё, что проверяет браузер (`required`, `maxlength`), обходится за минуту. Важные проверки повторяем на сервере.
- **Подделка имени.** См. предыдущий раздел: без входа по паролю любой может назваться кем угодно.

| Что нужно | Как написать |
|---|---|
| Форма, которая отправляет POST | `<form method="post" action="{{ url_for('send') }}">` |
| Поле, которое попадёт на сервер | `<input name="text">` |
| Маршрут для POST | `@app.route("/send", methods=["POST"])` |
| Значение поля формы | `request.form.get("text", "")` |
| Параметр из адреса (GET) | `request.args.get("name", "")` |
| Перенаправить | `return redirect(url_for("index", name=name))` |
| Ответ с ошибкой | `return render_template(...), 400` |
| Обратный порядок в шаблоне | `{% for m in messages|reverse %}` |
