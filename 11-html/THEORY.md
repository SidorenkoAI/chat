# Урок 11. HTML — теория и разбор кода

Наш чат уже умеет многое: несколько пользователей, личные сообщения, пароли, шифрование. Но пользоваться им можно только из чёрного окна консоли. В этой части курса мы сделаем чату **веб-интерфейс**: страницу, которая открывается в браузере на компьютере и на телефоне.

Сегодня — первый шаг: учимся описывать страницу на языке **HTML** и рисуем макет окна чата. Весь код урока — один файл `index.html`.

## Из чего состоит сайт

Сайт — это обычные текстовые файлы, которые умеет читать **браузер** (Chrome, Edge, Firefox…):

| Файл | Язык | За что отвечает | Урок |
|---|---|---|---|
| `index.html` | HTML | **что** есть на странице: заголовки, текст, кнопки | 11 |
| `style.css` | CSS | **как** это выглядит: цвета, размеры, расположение | 12 |
| `app.js` | JavaScript | **как себя ведёт**: что происходит при нажатии кнопки | 13 |

Удобно представить дом: HTML — стены и комнаты, CSS — обои и мебель, JavaScript — электричество и выключатели.

**HTML — язык разметки, а не программирования.** В нём нет переменных, условий и циклов. Мы просто размечаем содержимое: «это заголовок», «это абзац», «это поле ввода».

## Подробный разбор: тег, элемент, атрибут

```html
<h1>Школьный чат</h1>
```

- `<h1>` — **открывающий тег**. Имя тега пишется в угловых скобках. `h1` значит heading 1, заголовок первого уровня, самый крупный.
- `Школьный чат` — **содержимое**.
- `</h1>` — **закрывающий тег**, такой же, но со слешем `/`.
- Всё вместе — **элемент** «заголовок».

Элементы можно вкладывать друг в друга:

```html
<p>Вы вошли как <b>Аня</b></p>
```

Здесь элемент `<b>` лежит внутри элемента `<p>`. Закрывать нужно в обратном порядке, как матрёшки: сначала внутренний `</b>`, потом внешний `</p>`.

Некоторым тегам содержимое не нужно, и закрывающего тега у них нет. Например, поле ввода: `<input>`.

**Атрибуты** — дополнительные настройки элемента. Они пишутся внутри открывающего тега в виде `имя="значение"`:

```html
<input id="text" type="text" placeholder="Сообщение…">
```

Здесь у поля ввода три атрибута: `id`, `type` и `placeholder`. Порядок атрибутов не важен.

## Шаг 1. Скелет страницы

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <title>Школьный чат</title>
</head>
<body>
  ...
</body>
</html>
```

Такой скелет есть у любой страницы в интернете. Разберём каждую строку.

**`<!DOCTYPE html>`** — не тег, а пометка для браузера: «это современный HTML». Без неё браузер включает «режим совместимости» со страницами 1990-х, и некоторые вещи начинают вести себя странно. Пишется один раз, самой первой строкой.

**`<html lang="ru">`** — корневой элемент, внутри него вся страница. Атрибут `lang="ru"` сообщает язык страницы. Он нужен, например, чтобы браузер правильно переносил слова и не предлагал «перевести с русского».

**`<head>`** — «голова», служебная часть. Всё, что внутри, **на странице не показывается**. Это сведения о странице для браузера.

**`<meta charset="utf-8">`** — в какой кодировке записан файл. UTF-8 — кодировка, в которой есть все буквы всех языков и эмодзи. Мы уже встречали её на уроке 1, когда переводили строки в байты: `text.encode("utf-8")`. Если эту строку забыть, русские буквы могут превратиться в «кракозябры».

**`<title>Школьный чат</title>`** — название **вкладки браузера** (и закладки, если сохранить страницу). На самой странице этот текст не виден.

**`<body>`** — «тело», всё видимое содержимое страницы. Дальше мы работаем только внутри него.

**Отступы** (два пробела перед вложенными тегами) браузеру не нужны, он их не замечает. Они нужны людям: по отступам видно, что внутри чего лежит. В отличие от Python, где отступы — часть языка, в HTML это просто аккуратность. Но очень полезная.

## Шаг 2. Шапка

```html
<header>
  <h1>Школьный чат</h1>
  <p>Вы вошли как <b>Аня</b></p>
</header>
```

- **`<header>`** — шапка страницы. Сам по себе этот тег ничего не меняет на экране, но говорит браузеру и людям: «это верхняя часть с названием».
- **`<h1>`** — главный заголовок страницы. Бывают `<h1>`…`<h6>`: от самого важного к наименее важному. Мы ещё встретим `<h2>`.
- **`<p>`** — paragraph, абзац текста.
- **`<b>`** — bold, жирный. Имя пользователя выделено, чтобы бросалось в глаза.

### Подробный разбор: блочные и строчные элементы

Почему `<h1>` и `<p>` встали каждый на свою строку, а `<b>` остался внутри строки?

- **Блочные** элементы (`<h1>`, `<p>`, `<div>`, `<header>`, `<section>`, `<ul>`…) занимают всю ширину и начинаются с новой строки. Как кирпичи, которые кладут друг на друга.
- **Строчные** элементы (`<b>`, `<span>`, `<a>`, `<input>`, `<button>`…) живут внутри строки текста, как слова в предложении.

Это поведение «по умолчанию». На уроке 12 мы научимся его менять с помощью CSS.

## Шаг 3. Сообщения

```html
<main>
  <section id="messages">
    <div class="message system">Боря присоединился к чату</div>

    <div class="message">
      <b class="author">Боря</b>
      <span class="text">Привет всем!</span>
    </div>
    ...
  </section>
  ...
</main>
```

- **`<main>`** — главная часть страницы, ради которой её открыли. У нас это сообщения и список «В сети».
- **`<section id="messages">`** — раздел страницы. Атрибут `id="messages"` даёт разделу **уникальное имя**.
- **`<div>`** — «просто блок», коробка без особого смысла. Это самый частый тег в вёрстке: им группируют всё, что нужно сложить вместе. Каждое сообщение — отдельный `<div>`.
- **`<span>`** — то же самое, но строчное: коробка для кусочка текста.

### Подробный разбор: `id` и `class`

Сейчас эти атрибуты ничего не меняют на экране. Это **ярлыки**, по которым потом будут находить элементы:
- CSS (урок 12) — чтобы покрасить, например, все `.message` в виде «пузырей»;
- JavaScript (урок 13) — чтобы, например, найти `#messages` и добавить туда новое сообщение.

| | `id` | `class` |
|---|---|---|
| Сколько может быть на странице | **один** элемент с таким именем | сколько угодно элементов |
| Для чего | «вот этот конкретный элемент» | «все элементы такого вида» |
| Пример | `id="messages"` — список сообщений один | `class="message"` — сообщений много |

**Несколько классов сразу.** Классы перечисляются через пробел:

```html
<div class="message system">...</div>
<div class="message mine">...</div>
<div class="message private">...</div>
```

Каждое из этих сообщений — `message` (сообщение вообще), и у каждого есть уточнение: `system` (системное), `mine` (моё), `private` (личное). На уроке 12 общий вид всех сообщений мы опишем один раз для `.message`, а для уточнений допишем только отличия.

Эти виды соответствуют типам сообщений нашего протокола из уроков 5–8:

| Тип в протоколе | Как выглядит в макете |
|---|---|
| `{"type": "system", ...}` | `<div class="message system">` |
| `{"type": "message", "from": "Боря", ...}` | `<div class="message">` |
| `{"type": "message", "from": <я>, ...}` | `<div class="message mine">` |
| `{"type": "private", ...}` | `<div class="message private">` |

Внутри сообщения автор (`<b class="author">`) и текст (`<span class="text">`) лежат в отдельных элементах. Так их можно будет оформить по-разному: имя мелко и цветом, текст обычным шрифтом.

## Шаг 4. Список «В сети»

```html
<aside>
  <h2>В сети</h2>
  <ul id="online">
    <li>Аня</li>
    <li>Боря</li>
    <li>Вова</li>
  </ul>
</aside>
```

- **`<aside>`** — «боковая» часть страницы: то, что относится к главному, но не является им самим.
- **`<h2>`** — заголовок второго уровня, поменьше `<h1>`.
- **`<ul>`** — unordered list, список «с точками». Бывает ещё `<ol>`, ordered list, — нумерованный.
- **`<li>`** — list item, один пункт списка. Внутри `<ul>` могут лежать только `<li>`.

Пока список написан вручную. На уроке 16 его будет заполнять JavaScript по ответу сервера на команду `who`.

## Шаг 5. Форма отправки

```html
<footer>
  <form id="send-form">
    <input id="text" type="text" placeholder="Сообщение…" autocomplete="off">
    <button type="submit">Отправить</button>
  </form>
</footer>
```

- **`<footer>`** — «подвал», нижняя часть страницы.
- **`<form>`** — форма: группа полей, которые отправляются вместе. Форма удобна тем, что сама понимает клавишу **Enter**. Нажал Enter в поле — форма «отправилась», как будто нажали кнопку.
- **`<input>`** — поле ввода. У него нет закрывающего тега. Атрибуты:
  - `type="text"` — обычный текст. Бывают `password` (точки вместо букв), `number`, `email`, `checkbox`…
  - `placeholder="Сообщение…"` — серая подсказка внутри пустого поля;
  - `autocomplete="off"` — не предлагать то, что вводили раньше. Для чата подсказки браузера только мешают.
  - `id="text"` — чтобы JavaScript потом нашёл это поле и прочитал, что в нём написано.
- **`<button type="submit">`** — кнопка, которая отправляет форму.

Если сейчас нажать «Отправить», страница перезагрузится, и текст пропадёт. Так работает форма «по умолчанию»: она отправляет данные на сервер и загружает ответ. Сервера у нас пока нет. На уроке 13 мы отменим это поведение и будем обрабатывать отправку сами, на JavaScript.

## Подробный разбор: дерево страницы и инструменты разработчика

Браузер читает HTML и строит из него **дерево** (DOM, Document Object Model, «объектная модель документа»):

```
html
├── head
│   ├── meta
│   └── title
└── body
    ├── header
    │   ├── h1
    │   └── p
    │       └── b
    ├── main
    │   ├── section#messages
    │   │   ├── div.message.system
    │   │   ├── div.message
    │   │   └── ...
    │   └── aside
    │       ├── h2
    │       └── ul#online
    │           └── li, li, li
    └── footer
        └── form#send-form
            ├── input#text
            └── button
```

Запись `section#messages` значит «section с id messages», а `div.message.system` — «div с классами message и system». Эта же запись используется в CSS и JavaScript, мы встретим её на следующих уроках.

Увидеть дерево можно в **инструментах разработчика**: клавиша **F12** (или правый клик → «Просмотреть код») → вкладка **Elements** (в русском интерфейсе — «Элементы»). Там можно:
- навести мышь на тег — элемент подсветится на странице;
- раскрывать и сворачивать вложенные теги;
- двойным щелчком поменять текст или атрибут и сразу увидеть результат.

Правки в инструментах разработчика **не сохраняются в файл**. После F5 страница снова загрузится из `index.html`. Это удобно, чтобы пробовать, ничего не ломая.

## Подробный разбор: почему браузер не ругается на ошибки

Python на ошибке останавливается и пишет `SyntaxError`. Браузер так не делает: если в HTML ошибка (например, забыли `</b>`), он **молча пытается угадать**, что имелось в виду, и рисует как получится. Например, весь текст после незакрытого `<b>` может стать жирным.

Поэтому ошибки в HTML надо искать глазами:
- PyCharm подсвечивает незакрытые и лишние теги;
- в инструментах разработчика (F12) видно, как браузер на самом деле понял ваше дерево. Если `<aside>` вдруг оказался внутри сообщения, значит, где-то не закрыт `</div>`.

## Шпаргалка: теги этого урока

| Тег | Что это | Блочный? |
|---|---|---|
| `<h1>`…`<h6>` | заголовки | да |
| `<p>` | абзац | да |
| `<b>` | жирный текст | нет |
| `<div>` | блок-«коробка» | да |
| `<span>` | строчная «коробка» | нет |
| `<header>`, `<main>`, `<footer>` | шапка, главная часть, подвал | да |
| `<section>`, `<aside>` | раздел, боковая часть | да |
| `<ul>`, `<ol>`, `<li>` | список с точками, нумерованный, пункт | да |
| `<form>` | форма | да |
| `<input>` | поле ввода (без закрывающего тега) | нет |
| `<button>` | кнопка | нет |
| `<a href="...">` | ссылка (в заданиях) | нет |
| `<table>`, `<tr>`, `<td>` | таблица (в заданиях) | да |
