# Git и GitHub с нуля (дополнение к уроку 4)

Ты только что разложил чат по папкам и файлам. Теперь самое время научиться **сохранять историю проекта** и **хранить копию в интернете**. Для этого есть две вещи: **Git** и **GitHub**.

Мы разберём самый простой сценарий, без лишнего: **закоммитить и отправить на GitHub**. Больше ничего не нужно, ни веток, ни слияний. Каждый шаг расписан с нуля: что нажать, что напечатать и что должно появиться на экране.

> Если на каком-то шаге получилось не то, что написано в блоке «Что должно получиться», не иди дальше. Сначала загляни в раздел 11 «Если что-то пошло не так» или позови учителя.

## 0. Что это и зачем

**Git** — программа на твоём компьютере, которая запоминает **историю изменений** проекта. Представь компьютерную игру с сохранениями: прошёл уровень — сохранился; что-то пошло не так — вернулся к сохранению. Git делает то же самое с твоим кодом.

**GitHub** — сайт, где можно хранить копию проекта в интернете. Это даёт три вещи:
- **запасная копия**: сломался компьютер или удалил папку — код остался на GitHub;
- **можно показать код** учителю, другу или будущему работодателю (достаточно прислать ссылку);
- **можно работать с разных компьютеров**: дома и в школе.

Git и GitHub — это **разные вещи**. Git живёт на твоём компьютере, GitHub — в интернете. Они умеют общаться между собой.

### Как отправляется код: аналогия с посылкой

Три главные команды удобно запомнить как отправку посылки:

| Команда | Что происходит | В жизни |
|---|---|---|
| `git add` | выбираем, какие изменения пойдут в «посылку» | положил вещи в коробку |
| `git commit` | фиксируем «посылку» в истории и подписываем её | заклеил коробку и написал на ней, что внутри |
| `git push` | отправляем посылку на GitHub | отнёс на почту |

### Словарик

- **Репозиторий** — папка с проектом, за которой следит Git (вместе с историей).
- **Коммит** — одно «сохранение» в истории: набор изменений и короткая подпись к ним.
- **GitHub-репозиторий** — копия репозитория на сайте GitHub.
- **origin** — «прозвище» адреса твоего репозитория на GitHub. Так принято, это слово мы будем печатать в командах.
- **push** (читается «пуш») — отправить свои коммиты на GitHub.

## 1. Установи Git

### Windows

1. Открой в браузере сайт **https://git-scm.com/download/win**. Скачивание должно начаться само. Если нет, нажми на ссылку **64-bit Git for Windows Setup**.
2. Запусти скачанный файл (`Git-2.xx.x-64-bit.exe`). Если Windows спросит «Разрешить этому приложению вносить изменения?», нажми **Да**.
3. Откроется мастер установки. Почти везде нужно просто нажимать **Next**. Два места требуют внимания:
   - Экран **Choosing the default editor used by Git** («Выбор редактора по умолчанию»). Выбери в списке **Use Notepad as Git's default editor** («Блокнот»). Так будет проще, если Git вдруг откроет редактор. Если такого пункта нет, оставь как есть.
   - Экран **Adjusting the name of the initial branch** (если он есть): выбери **Override the default branch name for new repositories** и оставь имя `main`.
4. На остальных экранах оставляй всё как есть и жми **Next**, в конце — **Install**, потом **Finish**.
5. **Полностью закрой PyCharm и открой снова.** Без этого он не узнает, что Git установился.

### macOS и Linux (если у тебя не Windows)

- **macOS:** открой Терминал и напечатай `git --version`. Если Git нет, macOS сама предложит установить «Command Line Tools». Согласись.
- **Linux (Ubuntu):** `sudo apt install git`.

### Проверка

Открой PyCharm и внизу вкладку **Terminal** (терминал). Напечатай команду и нажми Enter:

```bash
git --version
```

**Что должно получиться:** строка вроде

```
git version 2.43.0.windows.1
```

(цифры могут быть другими, это нормально).

**Если не так:** «`git` не является внутренней или внешней командой» (или `command not found`). Значит, PyCharm не видит Git. Закрой PyCharm полностью и открой снова. Если не помогло, перезагрузи компьютер, а потом позови учителя.

## 2. Заведи аккаунт на GitHub

> Если у тебя уже есть аккаунт GitHub, пропусти этот раздел и переходи к «Адрес для коммитов» в конце.

1. Открой **https://github.com** и нажми **Sign up** («Зарегистрироваться»).
2. Введи **адрес электронной почты** (тот, к которому у тебя есть доступ: на него придёт код).
3. Придумай **пароль**. Лучше длинный и такой, чтобы ты его запомнил. **Запиши его в тетрадь** и никому не показывай.
4. Придумай **имя пользователя** (username). Это часть адреса твоих репозиториев: `github.com/ИМЯ/…`. Пиши только латинскими буквами, цифрами и дефисом. Выбирай имя, которое **не выдаёт лишнего**: без телефона, точного адреса и даты рождения. Хорошо подойдёт, например, `ivan-codes`.
5. Реши «капчу» (картинку-головоломку) и нажми **Create account**.
6. GitHub пришлёт на почту **код подтверждения**. Найди письмо, введи код на сайте.
7. Дальше сайт будет задавать вопросы про твои интересы. Всё это можно пропустить (**Skip**).

**Что должно получиться:** ты зашёл на сайт под своим именем, в правом верхнем углу есть твой кружок-аватар.

### Адрес для коммитов (чтобы не светить настоящую почту)

Каждый коммит подписан твоим именем и адресом почты, а на GitHub подписи видны всем. Чтобы **не показывать настоящую почту**, GitHub выдаёт специальный адрес-«заменитель». Найдём его:

1. Нажми на **аватар** в правом верхнем углу → **Settings**.
2. В меню слева выбери **Emails**.
3. Убедись, что стоит галочка **Keep my email addresses private** («Скрывать мой адрес почты»). Если её нет, поставь.
4. Чуть ниже будет написано что-то вроде

   ```
   Use this email address for web-based Git operations: 12345678+ivan-codes@users.noreply.github.com
   ```

   Этот адрес (`…@users.noreply.github.com`) **скопируй и сохрани**, он понадобится в следующем разделе.

## 3. Представься Git'у (делается один раз)

Git должен знать, кто делает коммиты. Это настраивается **один раз на компьютере**. В терминале PyCharm напечатай по очереди три команды. Каждую заканчивай Enter.

```bash
git config --global user.name "Ivan"
git config --global user.email "12345678+ivan-codes@users.noreply.github.com"
git config --global init.defaultBranch main
```

Что здесь написано:
- Первая команда: **имя**, которое будет стоять под коммитами. Пиши любое своё (лучше латиницей), кавычки оставь.
- Вторая: **адрес-заменитель** из прошлого раздела. Вставь **свой**, а не мой пример.
- Третья: у главной линии истории проекта должно быть имя `main` (так принято на GitHub). Просто напечатай как есть.

> Кавычки `"` нужны. Между `--global` и `user.name` один пробел, внутри `user.name` пробелов нет.

**Проверка:**

```bash
git config --global --list
```

**Что должно получиться:** в списке есть три твоих строки:

```
user.name=Ivan
user.email=12345678+ivan-codes@users.noreply.github.com
init.defaultbranch=main
```

(если в списке есть и другие строки, это нормально).

## 4. Создай репозиторий на GitHub

Сначала создадим «пустую полку» на сайте, куда потом отправим код.

1. На GitHub нажми **«+»** в правом верхнем углу → **New repository**.
2. **Repository name** — имя репозитория. Напиши `python-socket-chat` (латиницей, без пробелов).
3. **Description** можно оставить пустым или написать «Учебный чат на сокетах».
4. **Public / Private.** Выбери **Public**: тогда учитель сможет открыть твой репозиторий по ссылке. Но помни главное правило: **в репозиторий нельзя класть пароли и секретные ключи**. Дальше мы настроим файл, который этого не допустит.
5. **Самое важное:** **не ставь** галочки **Add a README file**, **Add .gitignore** и **Choose a license**. Репозиторий должен остаться **совсем пустым**. Если поставить галочки, GitHub сам положит туда файл, и первая отправка не получится.
6. Нажми зелёную кнопку **Create repository**.

**Что должно получиться:** откроется страница с твоим пустым репозиторием. Сверху есть адрес вида

```
https://github.com/ivan-codes/python-socket-chat.git
```

**Скопируй этот адрес** (кнопка копирования рядом с ним; убедись, что выбрана вкладка **HTTPS**). Он нужен на шаге 8.

> Ниже на этой странице GitHub покажет свои подсказки с командами («…or create a new repository on the command line»). **Не копируй их.** У нас свой, более простой набор команд.

## 5. Подготовь папку проекта

Теперь вернёмся к твоему компьютеру. Нужна **папка проекта**: та, в которой лежат `common`, `server`, `client` и `requirements.txt` (твой код урока 4).

> Дальше в курсе мы будем развивать **этот же проект**, поэтому лучше хранить его в одной папке на весь курс.

1. В PyCharm открой эту папку как проект (**File → Open…** и выбери папку).
2. Открой терминал внизу (вкладка **Terminal**). В начале строки терминала написан путь к текущей папке. Убедись, что это **папка проекта**.
3. Проверь, что в ней лежит твой код:

   ```bash
   dir
   ```

   (на macOS и Linux: `ls`). В списке должны быть `client`, `common`, `server`, `requirements.txt`.

   **Если не так:** терминал открыт не в той папке. Перейди командой `cd` с путём к папке проекта, например `cd C:\Users\Ivan\python-socket-chat`.

4. Скажи Git'у, что за этой папкой надо следить:

   ```bash
   git init
   ```

**Что должно получиться:**

```
Initialized empty Git repository in C:/Users/Ivan/python-socket-chat/.git/
```

В папке появилась **скрытая** папка `.git`. Там Git хранит всю историю. **Не удаляй её и ничего в ней не меняй.** Если её удалить, история пропадёт.

> С этого момента в начале строки терминала может появиться слово `(main)` или похожее. Это нормально.

## 6. Файл `.gitignore`: что в репозиторий не кладём

Не всё, что лежит в папке, нужно хранить в истории. Например, папка `.venv` (библиотеки, тысячи файлов, у каждого свои) в Git не нужна. Особенно **нельзя** отправлять на GitHub секретные ключи. Файл `.gitignore` («игнорировать») — это список того, что Git должен **не замечать**.

### Создай файл

1. В PyCharm в левой панели нажми правой кнопкой на **папку проекта** (самую верхнюю) → **New → File**.
2. Назови файл ровно так: `.gitignore` (с точкой в начале, без расширения).
3. Вставь в него:

   ```
   .venv/
   __pycache__/
   *.pyc
   .idea/
   chat.db
   certs/
   ```

4. Сохрани (Ctrl+S).

Что означают строки:

| Строка | Что игнорируем | Почему |
|---|---|---|
| `.venv/` | виртуальное окружение | это тысячи чужих файлов, их можно заново установить |
| `__pycache__/` и `*.pyc` | служебные файлы Python | Python создаёт их сам |
| `.idea/` | настройки PyCharm | у каждого свои |
| `chat.db` | база данных чата | появится на уроке 6, в ней будут люди и их данные |
| `certs/` | сертификаты и **приватный ключ** | появятся на уроке 9, ключ нельзя публиковать |

Файлов `chat.db` и `certs/` у тебя пока нет, и это нормально: мы записываем правило заранее. Позже в курсе встретится ещё одна строка, мы её добавим.

> **Важно:** если создаёшь `.gitignore` не в PyCharm, а в Блокноте, то в окне «Сохранить как» выбери **Тип файла: Все файлы** и напиши имя в кавычках: `".gitignore"`. Иначе Windows добавит `.txt`, и файл не сработает. Не создавай этот файл командой `echo … > .gitignore` в PowerShell: она сохраняет файл в кодировке, которую Git не понимает.

## 7. Первый коммит

### 7.1. Посмотри, что видит Git

```bash
git status
```

`git status` («статус») — самая полезная команда. Она показывает, что сейчас происходит в проекте. Привыкай запускать её **перед каждым шагом**.

**Что должно получиться:**

```
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        .gitignore
        client/
        common/
        requirements.txt
        server/
```

Слово **Untracked** значит «не отслеживается»: Git видит файлы, но пока не следит за ними. В списке **нет** `.venv` и `__pycache__`: `.gitignore` работает.

> Сообщения Git на твоём компьютере могут быть **на русском** («Неотслеживаемые файлы», «Изменения, которые будут включены в коммит»). Смысл тот же.

### 7.2. Положи файлы в «посылку»

```bash
git add .
```

Обрати внимание: после `add` стоит **пробел и точка**. Точка означает «всё в этой папке».

Проверь:

```bash
git status
```

**Что должно получиться:** теперь файлы перечислены под надписью **Changes to be committed** («будут включены в коммит»), и перед ними написано **new file**:

```
Changes to be committed:
        new file:   .gitignore
        new file:   client/__init__.py
        new file:   client/__main__.py
        ...
```

> Если при `git add .` появились предупреждения вроде `warning: LF will be replaced by CRLF`, не пугайся. Это безобидное сообщение про переводы строк, ничего не сломалось.

### 7.3. Закрепи «посылку» в истории

```bash
git commit -m "Урок 4: структура проекта"
```

- `-m` («message», сообщение) — это подпись к коммиту. Она **в кавычках**.
- Хорошая подпись **короткая и говорит, что сделано**: «Урок 4: структура проекта», «Добавил логирование», «Исправил порт по умолчанию». Плохая подпись: «asdf», «правки», «123».

**Что должно получиться:**

```
[main (root-commit) 40c193a] Урок 4: структура проекта
 10 files changed, 125 insertions(+)
 create mode 100644 .gitignore
 create mode 100644 client/__init__.py
 ...
```

(цифры и количество файлов у тебя будут свои). Поздравляю: **первый коммит сделан**. Он уже есть на твоём компьютере, но в интернет ещё не отправлен.

> **Не забывай `-m`!** Если напечатать просто `git commit`, откроется редактор текста для подписи. Если открылось окно Блокнота, напиши подпись в первой строке, сохрани и закрой окно. Если же в терминале появился непонятный экран с тильдами `~` (это редактор Vim), нажми клавишу **Esc**, напечатай `:q!` и нажми Enter. Потом повтори команду, на этот раз с `-m`.

### 7.4. Посмотри историю

```bash
git log --oneline
```

**Что должно получиться:** одна строка на каждый коммит. Пока он один:

```
40c193a Урок 4: структура проекта
```

Если экран «завис» и внизу двоеточие, нажми клавишу **q**, чтобы выйти из просмотра.

## 8. Подключи GitHub и отправь код

### 8.1. Скажи Git'у адрес репозитория на GitHub

Вставь **свой** адрес, который скопировал в разделе 4 (мой — только пример):

```bash
git remote add origin https://github.com/ivan-codes/python-socket-chat.git
```

Здесь `origin` — прозвище адреса, а дальше сам адрес. Проверь:

```bash
git remote -v
```

**Что должно получиться:** адрес напечатан дважды, `(fetch)` и `(push)`:

```
origin  https://github.com/ivan-codes/python-socket-chat.git (fetch)
origin  https://github.com/ivan-codes/python-socket-chat.git (push)
```

Проверь по буквам: в адресе должно быть **твоё** имя пользователя и **твоё** имя репозитория.

### 8.2. Убедись, что главная линия называется `main`

```bash
git branch -M main
```

Эта команда ничего не напечатает. Она просто на всякий случай гарантирует, что главная линия истории называется `main`, как на GitHub.

### 8.3. Отправь код (push)

```bash
git push -u origin main
```

Расшифровка: «отправь (`push`) линию `main` по адресу `origin`». Ключ `-u` нужен **только в первый раз**: он запоминает связь, поэтому потом хватит просто `git push`.

**Вход в GitHub.** В первый раз GitHub должен убедиться, что это ты. Скорее всего, появится окно **Connect to GitHub** с кнопкой **Sign in with your browser**:
1. Нажми эту кнопку. Откроется браузер.
2. Если ты не вошёл в GitHub, войди (логин и пароль от аккаунта).
3. Нажми **Authorize** (разрешить).
4. Браузер напишет, что вход выполнен. Вернись в PyCharm.

**Что должно получиться** в терминале:

```
Enumerating objects: 15, done.
Counting objects: 100% (15/15), done.
...
To https://github.com/ivan-codes/python-socket-chat.git
 * [new branch]      main -> main
branch 'main' set up to track 'origin/main'.
```

Главное — строка `[new branch] main -> main` и отсутствие слова `error` или `fatal`.

> **Если терминал сам просит «Username» и «Password»:** обычный пароль от GitHub **не подходит**, GitHub его для Git не принимает. Нужен специальный «пароль-токен». Как его получить, написано в разделе 11 («Authentication failed»).

### 8.4. Посмотри результат на сайте

Открой страницу своего репозитория в браузере (`https://github.com/ИМЯ/python-socket-chat`) и **обнови её** (F5).

**Что должно получиться:** на странице видны папки `client`, `common`, `server` и файлы `requirements.txt`, `.gitignore`. **Нет** `.venv` и `__pycache__`. Над списком файлов написана подпись твоего коммита.

**Твой код теперь в интернете.**

## 9. Повседневный цикл: изменил → закоммитил → отправил

Всё, что мы делали до сих пор (установка, регистрация, `git init`, `remote add`), делается **один раз**. Дальше жизнь проще: у тебя всегда один и тот же короткий цикл из четырёх команд.

```bash
git status
git add .
git commit -m "Что я сделал"
git push
```

Попробуем прямо сейчас:

1. Открой любой файл проекта, например `common/config.py`, и добавь в конец строку-комментарий: `# Проверка Git`. Сохрани (**Ctrl+S**).
2. Посмотри, что заметил Git:

   ```bash
   git status
   ```

   Теперь файл в списке **Changes not staged for commit** («изменения не подготовлены») с пометкой **modified** («изменён»):

   ```
   Changes not staged for commit:
           modified:   common/config.py
   ```

3. Положи изменение в «посылку», закрепи и отправь:

   ```bash
   git add .
   git commit -m "Добавил комментарий в config.py"
   git push
   ```

   Теперь можно писать просто `git push`, без `-u origin main`.

4. Открой репозиторий на GitHub и обнови страницу. Нажми на значок часов с числом **commits** над списком файлов. Ты увидишь **историю**: уже два коммита. Нажми на последний: GitHub покажет, **что именно изменилось** (добавленные строки подсвечены зелёным, удалённые — красным).

**Золотые правила:**
- Коммить **часто** и понемногу: когда доделал одну понятную вещь (работающий кусок кода, исправленная ошибка).
- Не забывай **сохранять файлы** (Ctrl+S) перед `git add`, иначе Git увидит старую версию.
- Перед `git commit` и `git push` смотри `git status`: всегда понятно, где ты.
- **Никогда не кладём в репозиторий пароли и ключи.** Если случайно отправил, сразу скажи учителю.

> В PyCharm есть кнопки для Git (меню Git, значок коммита). Мы пользуемся терминалом: команды везде одинаковые, и ты понимаешь, что происходит на самом деле.

## 10. Шпаргалка

**Один раз на компьютере:**

| Команда | Что делает |
|---|---|
| `git config --global user.name "Имя"` | говорит Git'у твоё имя |
| `git config --global user.email "почта"` | говорит Git'у адрес для подписи |
| `git config --global init.defaultBranch main` | главная линия будет называться `main` |

**Один раз на проект:**

| Команда | Что делает |
|---|---|
| `git init` | включает слежение Git'а за папкой |
| `git remote add origin АДРЕС` | запоминает адрес репозитория на GitHub |
| `git branch -M main` | называет главную линию `main` |
| `git push -u origin main` | первая отправка на GitHub |

**Каждый раз, когда поработал:**

| Команда | Что делает |
|---|---|
| `git status` | показывает, что изменилось |
| `git add .` | кладёт все изменения в «посылку» |
| `git commit -m "Подпись"` | закрепляет «посылку» в истории |
| `git push` | отправляет коммиты на GitHub |
| `git log --oneline` | показывает историю коммитов |

## 11. Если что-то пошло не так

Читай сообщение об ошибке до конца: чаще всего Git сам объясняет, что не так.

**«`git` не является внутренней или внешней командой» / `git: command not found`**
Git не установлен или PyCharm о нём не знает. Закрой PyCharm полностью и открой снова. Если не помогло, проверь раздел 1 и перезагрузи компьютер.

**`fatal: not a git repository (or any of the parent directories): .git`**
Ты находишься не в папке проекта или не выполнил `git init`. Проверь путь в начале строки терминала и перейди в папку проекта командой `cd`. Если `git init` не делал, сделай его (раздел 5).

**`Author identity unknown` / «Please tell me who you are»**
Не выполнена настройка из раздела 3. Выполни команды `git config --global user.name …` и `git config --global user.email …`, а потом повтори `git commit`.

**`nothing to commit, working tree clean`**
Коммитить нечего: после прошлого коммита ничего не менялось. Возможно, ты не сохранил файл (Ctrl+S). Измени что-нибудь, сохрани и повтори.

**`no changes added to commit`, а файлы изменены**
Забыл `git add .` перед `git commit`. Выполни `git add .` и повтори коммит.

**`error: remote origin already exists.`**
Адрес уже записан (возможно, с опечаткой). Замени его на правильный:
```bash
git remote set-url origin https://github.com/ИМЯ/python-socket-chat.git
```
Проверь результат командой `git remote -v`.

**`remote: Repository not found.` / `fatal: repository '…' not found`**
Адрес с опечаткой (чужое имя пользователя, лишняя буква, имя репозитория не совпадает) или репозиторий ещё не создан. Сравни результат `git remote -v` с адресом на странице репозитория и исправь командой `git remote set-url origin …` (см. выше).

**`fatal: Authentication failed` / `Permission denied` / `403`**
GitHub не принял вход. Разберись, какой случай у тебя:
- Ты ввёл **обычный пароль** от GitHub, а нужен **токен**. Получи его так: на GitHub аватар → **Settings** → в самом низу левого меню **Developer settings** → **Personal access tokens** → **Tokens (classic)** → **Generate new token (classic)**. В поле **Note** напиши «school», в **Expiration** выбери срок, поставь галочку **repo** и нажми **Generate token**. GitHub **один раз** покажет токен (он начинается с `ghp_`). Скопируй его сразу. Когда терминал снова спросит **Password**, вставь токен (при вставке на экране ничего не появляется, это нормально) и нажми Enter. Токен — это тот же пароль: **никому не показывай** и не пиши его в файлы проекта.
- Ты вошёл в браузере под **другим** аккаунтом. Выйди из него на github.com и войди под своим.

**`! [rejected] main -> main (fetch first)` / `Updates were rejected`**
На GitHub в репозитории уже что-то лежит (скорее всего, при создании ты поставил галочку **Add a README file**). Проще всего начать заново: на GitHub открой репозиторий → **Settings** → внизу **Danger Zone** → **Delete this repository**. Создай новый **пустой** репозиторий (раздел 4), потом выполни `git remote set-url origin НОВЫЙ_АДРЕС` и `git push -u origin main`. Если не уверен, позови учителя.

**`Could not resolve host: github.com` / долго нет ответа**
Нет интернета или сайт заблокирован школьным фильтром. Проверь, открывается ли github.com в браузере, и скажи учителю.

**В терминале появился странный экран с `~` (редактор Vim)**
Нажми **Esc**, напечатай `:q!` и нажми Enter. Потом повтори команду `git commit` вместе с `-m "…"`.

**Случайно отправил на GitHub пароль или секретный ключ**
Сразу скажи учителю. Такой пароль или ключ считается «утёкшим»: его придётся поменять.
