# Урок 2. Двусторонний чат в реальном времени — теория и разбор кода

На прошлом уроке клиент и сервер общались строго по очереди: клиент спросил — сервер ответил. Сегодня сделаем настоящую переписку: **обе стороны могут писать в любой момент**, и сообщение собеседника появляется сразу, даже если ты в это время ничего не отправлял.

## Проблема: два «ожидания» одновременно

Каждой стороне чата нужно одновременно:
1. ждать, пока человек напечатает строку (`input()`);
2. ждать, пока из сети придёт сообщение собеседника (чтение из сокета).

Обе операции **блокирующие**: программа останавливается на строчке и ждёт. Если программа «застряла» в `input()`, она не читает сокет — и входящие сообщения не появятся, пока ты сам что-нибудь не отправишь. Одна «линия выполнения» не может ждать двух событий сразу.

## Решение: потоки

**Поток (thread)** — это ещё одна «линия выполнения» внутри той же программы. Потоки работают **параллельно**:
- главный поток ждёт ввод с клавиатуры и отправляет сообщения;
- второй поток всё время читает сокет и печатает то, что пришло.

Каждый поток ждёт своего события и не мешает другому.

## Шаг 1. Сервер — `server.py`

### 1.1. Импорты и настройки

```python
import socket
import threading

HOST = "127.0.0.1"
PORT = 5555
```

- `threading` — стандартный модуль Python для работы с потоками. Всё остальное — как на уроке 1.

### 1.2. Функция приёма сообщений

```python
def receive_loop(conn: socket.socket) -> None:
    incoming = conn.makefile("r", encoding="utf-8", newline="\n")
    for line in incoming:
        text = line.rstrip("\n")
        print(f"\nКлиент: {text}\n> ", end="")
```

Эту функцию мы запустим в **отдельном потоке**.

- `conn: socket.socket` и `-> None` — это **аннотации типов**: подсказки для человека и для PyCharm, что функция принимает сокет и ничего не возвращает. Python их не проверяет, но PyCharm благодаря им лучше подсказывает методы.
- `conn.makefile(...)` — превращаем сокет в «файл», из которого удобно читать строки (как на уроке 1).
- `for line in incoming:` — бесконечно ждём и читаем строки от клиента. Цикл закончится, только когда клиент отключится.
- `print(f"\nКлиент: {text}\n> ", end="")` — разберём по частям:
  - `\n` в начале — перейти на новую строку, чтобы входящее сообщение не «прилипло» к тому, что ты сейчас печатаешь;
  - `Клиент: {text}` — само сообщение;
  - `\n> ` — снова нарисовать приглашение `> `, чтобы было видно, что можно продолжать печатать;
  - `end=""` — обычно `print` в конце добавляет перевод строки; здесь он не нужен, чтобы курсор остался сразу после `> `.

### 1.3. Запуск сервера и приём клиента

```python
def main():
    server_socket = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    server_socket.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    server_socket.bind((HOST, PORT))
    server_socket.listen(1)
    print(f"Сервер слушает {HOST}:{PORT}")

    conn, addr = server_socket.accept()
    print(f"Подключился клиент {addr}")
```

Этот блок полностью повторяет урок 1: создаём сокет, разрешаем повторно использовать адрес, привязываемся к адресу, слушаем и ждём одного клиента.

### 1.4. Запуск потока приёма

```python
    threading.Thread(target=receive_loop, args=(conn,), daemon=True).start()
```

Главная новая строчка урока. По частям:
- `threading.Thread(...)` — создаём объект потока. Пока он только создан, но не запущен.
- `target=receive_loop` — какую функцию выполнять в потоке. Обрати внимание: **без скобок**! Мы передаём саму функцию, а не вызываем её. Если написать `receive_loop(conn)`, функция запустится прямо здесь, в главном потоке, и программа навсегда застрянет в её цикле.
- `args=(conn,)` — аргументы для функции, **кортежем**. Запятая после `conn` обязательна: `(conn)` — это просто `conn` в скобках, а `(conn,)` — кортеж из одного элемента.
- `daemon=True` — поток-«демон» (фоновый). Программа не будет ждать его завершения при выходе. Без этого после `Ctrl+C` программа могла бы «висеть», потому что второй поток ещё жив и ждёт данных.
- `.start()` — запускаем поток. С этого момента `receive_loop` работает параллельно с остальным кодом `main`.

### 1.5. Главный цикл: ввод и отправка

```python
    while True:
        text = input("> ")
        conn.sendall((text + "\n").encode("utf-8"))
```

Пока второй поток слушает сокет, главный поток занимается своим делом: ждёт ввод и отправляет его клиенту. Строка отправки — та же, что на уроке 1: разделитель `\n`, перевод в байты, `sendall`.

### 1.6. Точка входа

```python
if __name__ == "__main__":
    main()
```

## Шаг 2. Клиент — `client.py`

Клиент устроен **зеркально** серверу. Отличия только в подключении и в подписи входящих сообщений.

### 2.1. Функция приёма

```python
def receive_loop(sock: socket.socket) -> None:
    incoming = sock.makefile("r", encoding="utf-8", newline="\n")
    for line in incoming:
        text = line.rstrip("\n")
        print(f"\nСервер: {text}\n> ", end="")
```

Такая же, как у сервера, только подпись «Сервер:».

### 2.2. Подключение и потоки

```python
def main():
    sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    sock.connect((HOST, PORT))
    print("Соединение установлено. Остановить клиента — Ctrl+C.")

    threading.Thread(target=receive_loop, args=(sock,), daemon=True).start()

    while True:
        text = input("> ")
        sock.sendall((text + "\n").encode("utf-8"))
```

- `connect` — клиент сам подключается к серверу (сервер при этом ждёт в `accept()`).
- Дальше всё то же самое: поток для приёма, главный цикл для отправки.

## Подробный разбор: как работают два потока

Представь, что в программе два сотрудника:
- **главный поток** сидит у клавиатуры: ждёт, пока ты напечатаешь, и отправляет;
- **поток приёма** сидит у «телефона» (сокета): ждёт звонка и записывает всё, что услышал, на экран.

Они работают одновременно и не ждут друг друга. Оба пользуются одним и тем же сокетом `conn`, но по-разному: один только **читает**, другой только **пишет**. Сокет это спокойно позволяет — чтение и отправка в TCP независимы.

А вот если бы **двое** одновременно писали в один сокет или меняли одну и ту же переменную, могла бы случиться путаница. Об этом (и о «блокировках», которые её предотвращают) — на уроке 3.

## Подробный разбор: почему `target=receive_loop`, а не `target=receive_loop(conn)`

Сравни:

```python
threading.Thread(target=receive_loop, args=(conn,))    # правильно
threading.Thread(target=receive_loop(conn))             # ошибка!
```

Во втором случае Python сначала **вызывает** `receive_loop(conn)` — прямо в главном потоке — чтобы узнать, что передать в `target`. А функция содержит бесконечный цикл чтения… Она никогда не вернёт результат, `Thread` так и не будет создан, и до `input()` программа не дойдёт. Правило: в `target` передаём **имя функции**, а её аргументы — отдельно в `args`.

## Подробный разбор: что такое поток-демон

Программа на Python завершается, когда закончились **все** обычные (не-демон) потоки. Наш поток приёма бесконечно ждёт данные в цикле — сам он не закончится. Если бы он был обычным, после выхода из `main` программа продолжала бы «висеть». `daemon=True` говорит: «этот поток вспомогательный, не жди его — завершайся, когда главный поток закончил».

## Как запустить и проверить

1. Запусти `server.py`, затем `client.py` (две вкладки консоли в PyCharm).
2. Напиши несколько сообщений подряд со стороны клиента — все появятся у сервера, без ответа.
3. Напиши с обеих сторон вперемешку — всё доходит в любом порядке.

## Частые ошибки

- **Входящее сообщение «разрывает» строку, которую ты печатаешь** — это ограничение простой консоли: два потока пишут в неё одновременно. На работу чата не влияет.
- **Программа не реагирует на `Ctrl+C`** — проверь, что у потока стоит `daemon=True`. В PyCharm используй кнопку **Stop**.
- **Сообщения не появляются, пока сам не напишешь** — забыли запустить поток (`.start()`) или вызвали функцию вместо передачи в `target`.
