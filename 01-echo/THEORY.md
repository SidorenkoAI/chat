# Урок 1. Сокеты и echo-сервер — теория и разбор кода

Сегодня мы пишем две самые простые сетевые программы: **сервер**, который ждёт подключения и отвечает клиенту тем же текстом, что получил (как эхо в горах), и **клиент**, который подключается к серверу, отправляет строки и печатает ответы.

## Основные понятия

- **Сокет** — «телефонная трубка» программы. У каждой из двух общающихся программ своя трубка, между ними — «провод» (соединение). Через сокет программа отправляет и получает данные.
- **IP-адрес** — адрес компьютера в сети («кому звоним»). `127.0.0.1` — особый адрес, означает «этот же компьютер» (его ещё называют `localhost`). С ним удобно тренироваться: сервер и клиент запускаются на одной машине.
- **Порт** — номер конкретной программы на компьютере («добавочный номер»). На одном компьютере одновременно могут работать много сетевых программ, и порт говорит, к какой именно из них мы обращаемся. Мы используем порт `5555`.
- **Клиент-серверная модель**: сервер запускается **первым** и ждёт; клиент подключается **сам**, по известному адресу и порту.
- **TCP** — способ передачи данных, при котором всё доставляется гарантированно и в правильном порядке. Но TCP передаёт не «сообщения», а **поток байтов** — сплошную ленту. Поэтому нужно самим договориться, где заканчивается одно сообщение. Наше правило: **каждое сообщение заканчивается символом перевода строки `\n`**.

## Шаг 1. Файлы урока

В PyCharm создай папку урока и в ней два файла: `server.py` и `client.py` (правой кнопкой по папке → **New → Python File**).

## Шаг 2. Сервер — `server.py`

### 2.1. Импорт и настройки

```python
import socket

HOST = "127.0.0.1"
PORT = 5555
```

- `import socket` — подключаем стандартный модуль Python для работы с сетью. Ничего устанавливать не нужно.
- `HOST` — адрес, на котором сервер будет ждать подключения. `127.0.0.1` значит «принимать подключения только с этого же компьютера».
- `PORT` — номер порта. Подойдёт любое число от 1024 до 65535, если его не занимает другая программа. Главное, чтобы у сервера и клиента он был **одинаковым**.

Имена написаны большими буквами — так в Python принято обозначать **константы**, то есть значения, которые не меняются во время работы программы.

### 2.2. Создание сокета

```python
def main():
    server_socket = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
```

- `def main():` — весь код сервера живёт в функции `main`. Так аккуратнее: переменные не «разбросаны» по файлу, а программу легко запустить одной строчкой.
- `socket.socket(...)` — создаём объект сокета.
- `socket.AF_INET` — используем адреса формата IPv4 (четыре числа через точку, как `127.0.0.1`).
- `socket.SOCK_STREAM` — используем TCP (надёжный поток). Есть ещё `SOCK_DGRAM` — это UDP: быстрее, но сообщения могут теряться и приходить не по порядку. Для чата это не годится.

### 2.3. Настройка повторного использования адреса

```python
    server_socket.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
```

- `setsockopt` — «установить опцию сокета».
- `SOL_SOCKET` — это общая настройка сокета (а не специальная настройка TCP).
- `SO_REUSEADDR` со значением `1` — разрешить занять адрес повторно.

Зачем: после остановки сервера операционная система ещё некоторое время держит порт «полузакрытым». Если в этот момент запустить сервер снова, получим ошибку `Address already in use` (на Windows — `WinError 10048`). Эта строчка разрешает сразу занять порт заново — очень удобно, когда сервер перезапускается после каждой правки кода.

### 2.4. Привязка к адресу и ожидание подключений

```python
    server_socket.bind((HOST, PORT))
    server_socket.listen(1)
    print(f"Сервер слушает {HOST}:{PORT}")
```

- `bind((HOST, PORT))` — «привязать» сокет к адресу и порту, то есть сказать системе: «все подключения на `127.0.0.1:5555` — мои». Обрати внимание на **двойные скобки**: `bind` принимает один аргумент — **кортеж** из адреса и порта.
- `listen(1)` — начать «слушать»: теперь сервер готов принимать подключения. Число `1` — размер очереди ожидающих подключений (сколько клиентов могут «стоять в очереди», пока сервер занят). Нам пока хватает одного.
- `print(f"...")` — f-строка: всё, что в фигурных скобках, подставляется значением переменной.

### 2.5. Приём подключения

```python
    conn, addr = server_socket.accept()
    print(f"Подключился клиент {addr}")
```

- `accept()` — ждать, пока подключится клиент. Это **блокирующий** вызов: программа «замирает» на этой строчке и ничего не делает, пока кто-то не подключится. Это нормально — сервер так и должен себя вести.
- `accept()` возвращает **два** значения, и мы сразу раскладываем их по двум переменным:
  - `conn` — **новый сокет** для общения именно с этим клиентом. Через него мы будем получать и отправлять сообщения.
  - `addr` — адрес клиента: кортеж вида `('127.0.0.1', 51234)` — IP и порт, который система выдала клиенту.

Важно не путать: `server_socket` только принимает новые подключения («вахтёр на входе»), а переписка идёт через `conn` («отдельный разговор с конкретным гостем»).

### 2.6. Чтение сообщений построчно

```python
    incoming = conn.makefile("r", encoding="utf-8", newline="\n")
```

- `makefile(...)` превращает сокет в объект, похожий на открытый текстовый файл. Из него можно читать **строками** — ровно так же, как из файла, открытого через `open()`.
- `"r"` — режим чтения (read).
- `encoding="utf-8"` — по сети приходят байты, а нам нужен текст. Эта настройка говорит, как превращать байты в буквы (кодировка UTF-8 умеет всё, включая кириллицу).
- `newline="\n"` — строки разделяются символом `\n`. Это и есть наше правило «конец сообщения».

Без `makefile` пришлось бы вручную получать куски байт через `recv()` и склеивать их, пока не встретится `\n`. `makefile` делает это за нас.

### 2.7. Главный цикл: получить и вернуть обратно

```python
    for line in incoming:
        text = line.rstrip("\n")
        print(f"Получено: {text}")
        conn.sendall((text + "\n").encode("utf-8"))
```

- `for line in incoming:` — перебираем строки, приходящие от клиента, одну за другой. Цикл **ждёт** следующей строки, если её ещё нет. Когда клиент отключится, строки закончатся, и цикл завершится сам.
- `line.rstrip("\n")` — убираем символ перевода строки с конца: он нужен был только как разделитель, в самом тексте он лишний.
- `print(...)` — показываем в консоли сервера, что пришло.
- `conn.sendall(...)` — отправляем ответ клиенту. Разберём выражение внутри по шагам:
  1. `text + "\n"` — добавляем разделитель, чтобы клиент понял, где конец ответа;
  2. `.encode("utf-8")` — превращаем строку в байты, потому что по сети передаются только байты;
  3. `sendall(...)` — отправляем **все** байты. (Есть ещё метод `send`, который может отправить только часть данных и сообщить, сколько успел; `sendall` сам дожимает остаток.)

### 2.8. Завершение работы

```python
    conn.close()
    server_socket.close()
```

Когда клиент отключился и цикл закончился, закрываем оба сокета — соединение с клиентом и «слушающий» сокет. Так мы вежливо освобождаем порт.

### 2.9. Точка входа

```python
if __name__ == "__main__":
    main()
```

Эта конструкция означает: «запусти `main()`, только если этот файл запустили напрямую (`python server.py`), а не импортировали в другой файл». Переменная `__name__` равна `"__main__"` только у файла, который запустили.

## Шаг 3. Клиент — `client.py`

### 3.1. Импорт и настройки

```python
import socket

HOST = "127.0.0.1"
PORT = 5555
```

Те же адрес и порт, что у сервера — клиент должен знать, куда подключаться.

### 3.2. Подключение к серверу

```python
def main():
    sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    sock.connect((HOST, PORT))
    incoming = sock.makefile("r", encoding="utf-8", newline="\n")
```

- Сокет создаётся точно так же, как на сервере.
- `connect((HOST, PORT))` — главное отличие от сервера. Сервер делал `bind` + `listen` + `accept`, то есть **ждал**. Клиент одной командой сам **идёт** к серверу. Если сервер в этот момент не запущен, получим ошибку `ConnectionRefusedError` — «в соединении отказано».
- `makefile(...)` — как и на сервере, чтобы читать ответы строками.

### 3.3. Цикл «отправил — получил ответ»

```python
    print("Соединение установлено. Остановить клиента — Ctrl+C.")
    while True:
        text = input("> ")
        sock.sendall((text + "\n").encode("utf-8"))
        reply = incoming.readline().rstrip("\n")
        print(f"Эхо: {reply}")
```

- `while True:` — бесконечный цикл: клиент работает, пока его не остановят.
- `input("> ")` — ждём, пока пользователь напечатает строку и нажмёт Enter. Это тоже **блокирующая** операция.
- `sock.sendall(...)` — отправляем строку на сервер по тем же правилам: `\n` в конце и перевод в байты.
- `incoming.readline()` — читаем **одну** строку ответа. Программа ждёт, пока ответ не придёт.
- `.rstrip("\n")` — убираем разделитель и печатаем.

Заметь: клиент строго чередует «отправил → ждёт ответ». Он не может получить сообщение, пока сам ничего не отправил. Это ограничение мы уберём на следующем уроке.

### 3.4. Точка входа

```python
if __name__ == "__main__":
    main()
```

То же самое, что у сервера.

## Подробный разбор: почему «блокирующие» вызовы — это важно

Сегодня встретилось три блокирующих вызова: `accept()`, чтение строки из сокета и `input()`. «Блокирующий» значит: программа останавливается на этой строчке и ждёт события (подключения, данных, нажатия Enter). Пока она ждёт одного — она **не может** делать ничего другого.

Для эхо-сервера это не проблема: всё происходит строго по очереди. Но попробуй представить чат, где сообщения могут прийти в любой момент, пока ты печатаешь своё… С одной «линией выполнения» так не получится. Решение — **потоки**, о них на уроке 2.

## Подробный разбор: байты и строки

Внутри Python текст — это строка (`str`). По сети передаются только байты (`bytes`). Поэтому:
- при отправке: `строка.encode("utf-8")` → байты;
- при получении: байты → строка (это за нас делает `makefile(..., encoding="utf-8")`).

Отправитель и получатель обязаны использовать **одинаковую** кодировку. Если одна сторона кодирует в UTF-8, а другая декодирует, например, в cp1251, вместо русских букв получатся «кракозябры».

## Как запустить и проверить

1. Запусти сервер: правой кнопкой по `server.py` → **Run 'server'**. В консоли появится «Сервер слушает 127.0.0.1:5555».
2. Запусти клиента: правой кнопкой по `client.py` → **Run 'client'**. PyCharm откроет вторую вкладку консоли.
3. Напиши что-нибудь в консоли клиента и нажми Enter. В консоли сервера появится «Получено: …», а в клиенте — «Эхо: …».

Остановить программу — красная кнопка **Stop** в PyCharm. (В обычном терминале на Windows сервер, ожидающий подключения в `accept()`, может не реагировать на `Ctrl+C` — тогда помогает `Ctrl+Break` или просто закрыть окно.)

## Частые ошибки

- **`ConnectionRefusedError`** — клиент запущен раньше сервера или порты не совпадают.
- **`Address already in use` / `WinError 10048`** — предыдущий сервер ещё работает (проверь, не осталась ли запущенной вкладка в PyCharm) или не хватает строки `SO_REUSEADDR`.
- **Клиент «завис» после отправки** — сервер не отправил `\n` в конце ответа, и `readline()` ждёт конца строки вечно.
